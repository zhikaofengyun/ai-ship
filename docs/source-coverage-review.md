## 对映射表容易夸大的地方

1. **泛型存储不等于业务功能。** P03/P04、N05、C02/C05/C08/C10、H02/H08/H09、O04/O05/O07、W06 等当前主要是配置或可复用基础。尤其 C10 的 Timeline ChangeSet 不能算运行图安全改图已经落地。
2. **分别核对自动分析与人工操作。** S02 提供文本/条件检索。B01 的自动分析提供起音候选，B02 的人工路线另支持实际试听、逐点标记普通拍点/强拍/段落、版本保存及向剪辑时间线映射。V04/V05 支持人工时间锚点，Y03 的本地渲染器为 FFmpeg。
3. **配置存档和执行命令是两件事。** 前端把配置保存到 `View.operation_scope.feature_configs`，通过 records API 创建/更新；`ConfigureFeature` 则验证路线/控件、登记 TaskContract 与 blocked Run。旧映射的 `contract_endpoint` 已在 `implementation-2` 拆为 `configuration`、`contract_request` 与 `execution`，不能把保存 View 或登记任务当业务完成。实际已接通路线走 `/execution/start` 或专用媒体/业务 API。
4. **参数解析器尚未贯穿渲染。** 六层参数继承/锁的独立函数与测试存在，但媒体执行消费已展平的 clip/recipe 数据；不能声称所有层、所有方向、所有关键帧/蒙版时钟已端到端打通。
5. **技术成功与业务成功分开。** 真实 FFmpeg、hash、QC、ZIP 是可执行事实；商品真实性、完整许可、实际平台帖子、真实指标与因果效果仍需独立证据。所有媒体产物保持 `publish_ready=false`。
6. **测试替身有明确范围。** 三角色协作与生成协议的测试服务核验接口、计费和异常。独立运行的 llama.cpp 加载真实 Qwen2.5 0.5B GGUF 并从原片候选中选择镜头。它在演示中判断错了顺序，人工接管后成片通过像素测量。另在三套真实权重接入后发现两张接受票的证据错误，原案受阻，单镜头人工接管成功。[三角色原始回执、修正与实片](../evidence/ai-production/ensemble/README.md)。参见 [原始提案、纠正和实片](../evidence/ai-production/demonstration/README.md)。
