# AI 制作台与项目内交接

项目列表、新建项目和切换项目进入制作台。普通侧栏保留项目、制作台和原文的八个分区，各模块在所在分区出现一次。素材库、工作流、Agent 团队、剪辑室、交付与数据面板通过相应业务模块或项目操作进入。旧的直接地址仍可打开。录入目标后可以选择本地画面分析、导演模型或异构小队。首次打开“模型配置”可以从服务端已登记并允许绑定的模型中选择，按键确认后会预填可编辑的项目配置。保存只登记绑定，可单独发起模型验证。已有绑定会从可新增选项中排除。具备三个不同模型时，小队初始分配三个角色。目标、素材选择、尺寸、帧率和本次模型费用上限可调，每次发起以所在项目、所选输入及实际服务为准。

| 用户操作 | 原文依据 | 数据如何流转 |
| --- | --- | --- |
| 新建项目后直接输入制作目标 | P01、C08、W01 | 读取 Project 中的目标、时长和画幅。本次任务的覆盖项独立保存在当前身份及项目的浏览器草稿。 |
| 导入和选择原片 | A01、N02、W03 | 用现有分块导入接口写入实际素材，可预览并按文件勾选。只将本次选中的可解码定时视频发送给制作服务。 |
| 按目标安排镜头 | C01、C08、C09、C11、N01–N03 | 本地路线按实帧取样、聚类和可用 OCR 工作，模型路线发送绑定输入，团队路线还要求复核和独立裁决。模型未配置、无法执行和外部结果未知均保留实际状态。 |
| 审阅具体依据 | C06、C09、N07、W04 | 点击镜头跳到该来源的准确入点，显示源区间、时间线位置、选用理由和待核实项。来源与最终成片共用剪辑室画面几何逻辑，可适配、填充、原像素缩放、平移、全屏，播放条按镜头源入出点定位。来源证据可展开查看取样时刻和识别结果，团队有返回时显示复核与裁决。 |
| 生成补充镜头 | G01–G06、N07 的相关子路线 | 在制作台上从原任务的缺口或选中镜头带入位置及目标。选择服务端登记的 ComfyUI 图片或视频工作流，调整提示词和种子。图片候选可先查看原图，再明确指定定格秒数和帧率；原图与独立的定时视频均保留。参考图生成视频时，可在此处选择项目中的原始图片及具体版本、选用刚生成的关键帧，或直接导入新的参考图，提交前能看到所选画面。文字生成的配置沿用自身输入。异步任务按原请求核对；队列状态与实际可用文件分别显示。输出实际到库后才加入选用范围。 |
| 可选的首镜原片文字 | N02、N03、C06、C07、W04 | 在制作目标下展开「首镜文字要求」，输入原片第一帧须清楚可见的字样。制作台按所选入点取实际帧，显示文字、时间和核验结果。审阅人可直接打开已核实的备选片段，确认来源、入出点及理由后生成独立候选。普通叙事偏好沿用自由选镜。采用、手动调整和渲染共享同一项明确约束。下载前再次从实际编码的第一帧提取证据。 |
| 只替换一段 | E06、E09、G06、N07 | 用户对选中的镜头指定新素材、源入点、源出点和改动理由。新方案保留原方案及未更改的镜头，可继续比较与采用。 |
| 采用与人工接管 | C06、E01、E08、W03、W04 | 明确采用后才创建 Timeline。接管链接带已批准时间线的实际身份，可在人工剪辑室调整、保存并返回同一制作任务。返回后默认按当前时间线起点排序，原始模型提案可单独切换核对。 |
| 锁版、导出与核对 | E08、Y01、Y04–Y06 | 提交前检查 Run、Timeline 修订。读取真实 Artifact、Audit 后才提供播放和下载。可展开尺寸、时长和整片解码等实际质检项。在成片下按当前文件版本登记内容或权利判断、创建发布意图、预检或登记已有回执；本地意图以单独的授权为后续发送条件。 |

制作记录按项目保存。点开历史可以在阻塞、审阅、已编排和已渲染的任务之间切换。浏览器收到不确认的提交结果时可用原幂等键核对。生成服务的候选可能存在版权、商品与语义未决项，文件可播放只证明素材已经入库。对于已导出的旧版本，时间线后续修改需另一次明确锁版和渲染。

## 界面依据

Apple 的 Layout 强调媒体与控件分层、渐进披露；Toolbars 说明应按任务选取常用命令并保持位置一致。这里将操作区与来源监视器并排，外层侧栏只保留项目切换和原文分区，镜头依据及历史按需展开。窄屏中审阅采用单列布局。用户可拖动或用键盘调整面板宽度，减少动态偏好由系统与应用设置共同决定。[Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout) · [Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars) · [Apple Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

[实际模型制作与纠正实录](../evidence/ai-production/demonstration/README.md)给出真实小型语言模型的选择、人工校正、最终导出，以及逐画面比较结果。

首镜核对使用 Tesseract 的词级文字、行信息、坐标和置信度，并用 FFmpeg 实际解码时间戳对应来源区间。服务只展示可核实的文字条件，用户可在新任务里删除或改写条件。[Tesseract 词级输出](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html) · [FFmpeg 的帧信息与滤镜](https://ffmpeg.org/ffmpeg-filters.html#showinfo)

## 复核方式

每组页面或交互调整前以原始 HTML 内的完整 atlas-data 与仓库合同做全量等值校验，核对 23 个模块、178 个功能、69 个场景，再回读表内涉及功能的具体目标与上下游。针对性执行证据来自 `scripts/browser_ai_production.py`，其中浏览器使用正在运行的真实本地服务。用例里的生成器是按 ComfyUI 异步协议返回真实测试视频的本地接口替身，生成权重与生产服务需另有实联证据。独立检查对下载成片进行 FFmpeg 全片解码，日志记录实际尺寸、时长和校验值。

交互实测覆盖单屏任务和上述部分原文交接。当前没有由此证明 178 个功能全部完成，也没有将片段的技术可用性视为商品和叙事语义已经通过验收。
