# 离线回放与提示词对照

工作台「运行底座 → H05 执行沙箱与资源边界」可以打开只读回放。H08 的「运行环境与配方」也可进入同一界面。选取某次工具调用，或输入历史记录 ID 和版本。选第二条记录可比较当时的消息、推理参数、模型配置、上下文证据与回答。还可以检查回答是否包含指定文字、JSON 是否有指定的顶层字段。两组判断都逐条应用于已经得到的回答。

服务从 SQLite 的只读快照中读取两个精确版本。模型调用发出前会保存请求选项和实际传输层追加的指令，消息正文复用原快照，并对完整 wire payload 验证摘要。历史版本可以重建当时的 wire 格式，只有重建摘要匹配才展示消息。新调用另记供应商提供的模型标识、系统指纹（如有）、响应 JSON 摘要和规范化回答摘要。未发出、发送未确认与收到供应商回执分别标识。截断、未知结果、响应不合格的调用不参加输出评测；来源撤权后的提示词与正文遮蔽，历史记录保留引用和原因。

平台事件可查看原事件的来源、观察时间、关联发布意图和去重证据。媒体生成及未识别工具提供已记录的元数据。回放路径无执行入口，不调用模型、媒体工具、支付或发布接口。等权的两条历史样本只能证明被检查输出间的异同。推理质量与业务表现仍需相应留出样本或真实观测。

| 功能图谱 | 已执行的边界 |
| --- | --- |
| H05，R1-19-X | 回放含外部发布副作用的工具记录与普通发布接口保存的人工回执，原账本和调用数不变。 |

通过 `GET /api/v1/harness/replay-evidence` 按项目分页找记录。`GET /api/v1/harness/replay-evidence/{id}` 需要 `project_id` 和 `version`，可同时传 `compare_id`、`compare_version`、`expected_text`、`json_key`。

运行 `python -m unittest tests.test_evidence_replay -v` 检查真实回环 HTTP、消息重建、部分失败遮蔽、撤权和只读账本。运行 `python scripts/browser_evidence_replay.py --output /tmp/ai-ship-replay` 检查浏览器内的双样本断言。测试使用回环协议夹具，首次请求和离线查看的供应商请求数分别为 2 与 0。[浏览器实测](../evidence/recorded-response/result.json) · [对照画面](../evidence/recorded-response/comparison.png)
