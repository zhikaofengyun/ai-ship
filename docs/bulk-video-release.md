# 从拍摄素材到下一版剪辑

工作从项目制作台开始。已有素材、生成服务、模板时间线、交付合同、后续工作流均按项目和版本绑定。每个作品有自己的时间线、状态和证据。团队可以在某个环节接手，也可以只运行本次需要的环节。

| 环节 | 操作者能做什么 | 下游如何核对 |
| --- | --- | --- |
| 确定创意依据 | 同步 Google Trends、三个 PeerTube 实例的热门视频，或有授权的 YouTube 地区榜；登记项目目标与本地化简报 | 保留来源原始身份、观察窗口、市场和有效期。转载的同一原视频可核对到相同身份 |
| 拿到可用原片 | 上传拍摄素材，观察已许可的拍摄目录，或从 Commons 检索导入 | 同路径新字节留下新版本，同字节不同来源仍保留证据，入库和导出复核当前用途 |
| 组合批次 | 在镜头槽放入原片区间或生成配置，复制人工时间线上的字幕、音轨和效果，或接独立子工作流 | 每条变体冻结组合、来源和工作流版本；生成中断按原请求核销。可查看单件状态并打开该时间线接管 |
| 分轮修订 | 导演按目标和版本化证据提案，复核意见、前轮失败、软偏好和硬约束分别记录 | 保存真实调用、检查点、预算、采用的证据和人工决定，局部修改未开始节点时保留已完成成果 |
| 验收与交付 | 绑定市场及输出合同，核验实际编码件的尺寸、时长和解码等要求 | 时间线预检、成片验收、人工交接、真实平台回执各自可查。迟到的成功回执归回原意图 |
| 解释表现 | 先把平台最终媒体核到导出原件，再选择账号、流量来源、发布后观察窗和成片位置比较 | 显示涉及多少帖子、哪些原片版本、用了多少处、是否有别的素材在该时段。无对应端点或没有进入该区间的观众分别统计 |
| 指导下一版 | 在表现表登记可能原因、反例、下一版改法与停止规则，冻结为一项可引用的选材假设 | 重新生成时核对原始样本是否变化。评分参数可以经独立留出集验证、人工发布、回滚 |

画面查找支持经固定权重校验的 CLIP。操作者可以用文字找到抽样画面、跳到原片时间，再决定是否给该位置打标。[实际画面检索与双浏览器定位](visual-frame-search.md)

中英文口播支持可选的离线 Vosk 逐词转录。字幕审核保留原录音、模型、逐词时码及人工修订。已在剪辑器导入并重新打开审核后的字幕。[中英文逐词记录与字幕回读](local-speech.md)

三模型评议在一次真实 CPU 运行中进行了两轮、六次推理。两轮均因模型对原片的引用未通过核对而停止自动交付。操作员另外创建并校正方案，保留原失败记录，再渲染出通过媒体检查的文件。[导演、复核、裁决与人工修订记录](../evidence/batch-production/agent-loop.json)

## 能力边界与容量

生产批次接受 1–100,000 条作品及最多 64 个有序镜头槽。独立工作线程和生成窗口另有上限。数量上限是接收边界。完成时间依赖媒体时长、分辨率、滤镜、模型、机器、存储与外部服务。以下数据来自不同实测，不折算为同一条生产线的持续吞吐。

| 实测 | 验证与范围 |
| --- | --- |
| [100,000 个队列工作项](../evidence/batch-production/queue-envelope.json) | 100,000 行持久化，完整枚举出相同数量的互异组合。核对幂等、尾页、暂停和取消；该组未编码 |
| [10,000 条时间线](../evidence/batch-production/capacity.json) | 四个工作线程持久化 10,000 条不同时间线，58.272 秒完成 |
| [1,000 条测试短片](../evidence/batch-production/thousand-renders.json) | 160×90、25 fps、每条 0.6 秒。227.444 秒完成编码生产。随后逐份下载及完整解码，1,000 个文件摘要互异 |
| [三条有声竖片](../evidence/batch-production/portrait-capacity.json) | 每条 1080×1920、15 秒、25 fps、H.264/AAC。两个工作线程在 19.514 秒完成批次，独立下载及复核用时 8.883 秒 |
| [实拍经模型选剪的成片](../evidence/batch-production/real-footage) | 从有作者和许可记录的真实 30.066 秒咖啡烘焙录像中选剪 9 秒，实际 Qwen2.5 0.5B 本地推理，核对画面后批准、下载、全片解码。该节选随原作使用 CC BY-SA 4.0 |

需要将 HTTP 服务与编码进程分开运行时，可在同一台机器使用相同的数据目录，分别启动 API 和独立工作进程。

```bash
python scripts/run.py --data-dir /srv/ai-ship --batch-workers 0
python scripts/run.py --data-dir /srv/ai-ship --batch-worker-only --batch-workers 2
```

## 审计与复现

以仓库内的原始 HTML 为准。23 个模块、178 项功能、534 条路线、742 个控件、1,104 条质量门槛、574 条失败路径均保留。可通过 [逐项审计](source-coverage-review.md) 查每项的可用行为和缺口，通过 [本轮质量门槛增量](batch-gate-evidence.md) 查具体证据，通过 [69 项场景](scenario-coverage.md) 查跨模块验证。14 条图谱路线已注册为通用工作流节点；许多其他子功能从各自的业务界面与 HTTP 操作执行。

安装开发依赖后，下面的命令可复核来源、接口、全部本地测试和双浏览器行为。每轮使用新的输出目录。

```bash
python -m pip install -r requirements-dev.txt
npm ci
python scripts/check_contracts.py
python scripts/export_contracts.py --check
python scripts/feature_workflow_audit.py --check
python scripts/run_regression.py --round 1 --webkit --output /tmp/ai-ship-release-round
```

真实平台 OAuth 同意、真实账号指标、远程自动发帖及撤下、商业剪辑软件往返、物理设备与多机生产负载需要各自的验证。上述测试数据区分公共网络观察、本地真实媒体、真实模型推理、合成投放数据和平台协议夹具。
