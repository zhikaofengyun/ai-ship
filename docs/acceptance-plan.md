# 余项验收与开发次序

最新逐项状态和实测证据请见[当前审计](source-coverage-review.md)及[批量制作证据](../evidence/batch-production)。以下计划保留当时的验收次序。

此清单不增加 Atlas 以外的新模块。它把独立审计中尚未通过的条件按依赖关系排序，用于接手人选择下一批开发；准确的逐项验收文字仍以 `contracts/atlas.json`、`contracts/implementation.json` 与 `scenario-coverage.md` 为准。不同方案仍由用户选择，顺序不是强制固定的生产流水线。

## 每个功能的统一交付单位

1. **源定位**：固定 feature/route/requirement ID、输入输出实体、原文质量门槛和失败条件。原文缺字段标明缺口；工程决定另存为工程规范。
2. **类型与语义**：列请求/响应、枚举、null/0/不适用、版本引用、媒体/业务时间、货币与误差。扩展字段不能代替领域验证。
3. **执行合同**：声明 capability、前置条件、当前授权、预算、时限、幂等键、检查点/恢复与无需发出的失败路径。未注册不要在UI显示“已接通”。
4. **交互与自由度**：说明入口、路线切换、人工锁、手工处理、撤销和草稿；明确引导用户处理字段/版本冲突，而非静默纠正。
5. **数据流**：画清真实消费字段/区间、输出版本、使用账本和影响回传；保留原件以及历史修订，不把导航图边复制成执行依赖。
6. **测试**：至少包含一条真实正向、一条失败/权限/无效输入、一条上游变化或断点恢复、一条下游消费验证。外部测试替身与真实服务结果分开保存。
7. **验收**：在相同冻结版本上记录命令、环境、输入/输出hash、回归证据及未覆盖项；仅当原文该项全部条件有直接证据时才更新完整验收状态。

## 生产前必须单独拿到的证据

真实供应商模型/价格/返回身份、获批的平台应用与账号权限、目标用途/市场的权利审核、目标设备 Safari/iPhone 与辅助技术、真实多用户并发和存储容量、实机备份恢复与快照后外部账单核对。这些是未来验收输入；本地模拟传输、合成媒体、源码检查和当前五轮回归不能替代它们。
