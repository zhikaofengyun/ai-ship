# 批量剪辑、混合生成与工作流接续

进入项目制作台的「批量制作」，按成片里的顺序添加镜头。每个镜头可以选择一个或多个已入库视频区间，也可以配置单独的生成提示词、模型、参考图与目标时长。提交后可以关闭网页，服务端继续在项目数据库中领取工作项。批次列表支持查看进度、失败原因、时间线、生成任务及成片，操作均限定在当前项目和租户。

| 制作方式 | 如何配置 | 实际结果 |
| --- | --- | --- |
| 素材库批剪 | 给每个镜头配置备选素材、固定版本、入点与出点 | 按种子遍历不重复的来源区间组合，每个序号产生一条独立时间线 |
| 文生或图生视频 | 为任意数量的镜头选择已注册的视频生成配置。需要参考图的配置必须选择本项目实际图片版本 | 逐槽提交、按原请求查询并解码返回文件，成功入库后取指定时长 |
| 已拍素材与生成补镜混编 | 在任意两个素材镜头之间插入生成镜头，也可将生成镜头用作片头或结尾 | 一个序号中的每一槽均有独立的来源与位置 |
| 参考人工手剪样片 | 指定已有 Timeline 的修订，给每个画面片段指定等长源区间的替选 | 保留原片段位置、轨道、速度、音量、额外音轨、字幕和兼容渲染的转场。字幕或配音仍须与换入画面符合创作意图 |
| 批次继续执行已保存的工作流 | 选择 Workflow 的准确版本，指定可接收 Timeline 或 Artifact 的节点与输入端口 | 每项获得独立的已绑定流程、子运行、节点检查点和输出引用。等待生成回执时保留同一子运行 ID |

## 生成和加工的范围

每个批次支持 1–100,000 个序号、1–64 个顺序槽，每个素材槽可选 1–64 个源区间。纯素材配方的组合上限为各槽候选数的乘积。序号到候选组合的映射可重放，软件无需展开整个笛卡尔积。如果配置了生成槽，每个序号与每一槽使用可追溯的不同种子。来源标识或种子不同仍可能得到观感相似的内容。已入库的生成视频、上传的素材、衍生版本和已导出的成片均可用作有时长的来源。

保存草稿会产出可接管的 Timeline。选择批量渲染会按提交范围锁定每项时间线，调用现有 FFmpeg 编码器，保留逐镜头 Usage、RenderManifest、TimeMap、Artifact 和技术质检。渲染沿用服务端的写入与审阅身份要求。发布仍须从发布流程确认。含人工字段锁或已绑定语义配音的手剪项目需要先制作允许换镜头的版本。依赖过期、素材撤权、原片实际时长不足或不支持的效果会留下具体错误。

制作台的单导演、多角色 AI 导演仍可用于决定镜头。这里的纯素材组合执行明确提供的镜头区间，具体的变体预算与素材选择可以由上游工作流决定。

## 工作进程与恢复

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `AI_SHIP_BATCH_WORKERS` | 2 | 每个 API 进程启动的后台线程数。取值 0–16，0 仅提供提交与查询，可让共享同一数据库的另一个服务进程领取。多个进程的线程数会相加 |
| `generation_window` | 4 | 单批同时推进的含生成工作的序号数，范围 1–16。每个媒体配方序号依次完成其生成槽，然后才继续下一槽。接续的 DAG 按该图已定义的节点调度 |
| `max_generation_calls` | 未指定时按配方计算 | 用户可设置本批推理请求数上限。入队前计算序号数乘以每项的生成槽数与接续流程固定生成节点数之和，超过上限的批次整体拒绝 |
| `AI_SHIP_DATA_DIR` / `AI_SHIP_DB` | 沿用项目配置 | SQLite WAL 保存批次、原配方、序号、生成槽回执、执行租约、时间线与结果引用。生产 worker 需要访问相同的媒体对象和数据库 |

生成上限统计本地生成适配器的新推理任务，查询既有回执不重复计数。这是**推理次数**预算。它不估算电费、GPU 分钟、供应商单价、成片存储或模型 token；其它工作流操作仍受各自配置的步骤、时间、尝试次数和适配器准入限制。提交批次时写入的 `generation_limit` 是该配方可能提交的新生成任务数，重试沿用同一请求键。

暂停后停止领取新序号，已经开始的本地操作可到达安全点。取消保留已经完成的时间线和产物，未启动的序号被取消。已经提交的生成只核对或取消原供应商任务。生成回执未知会保存任务 ID 并暂停配方的进一步提交，修复后可先重试失败项再恢复批次。对已经重做或已经有副作用的步骤，接续工作流使用既有子运行的恢复或核对入口。

每个序号有独立租约和 fencing token。进程退出后，租约过期的工作项可以由另一个进程接管。时间线创建与其队列回执同一个事务提交。渲染进程在已写出成片后中断时，恢复按精确时间线 ID 和修订查找并核对已有产物。实际字节与外部提交结果都通过现有服务核对。本地 SQLite 部署没有跨机器的调度或存储吞吐保证。

## API

所有操作均沿用已有身份和 `{data, trace_id}` 返回格式。

| 方法 | 路径（前缀 `/api/v1/production/batches`） | 用途 |
| --- | --- | --- |
| POST | 根路径 | 冻结配方、检查来源、生成次数与项目范围，并原子写入所有序号。同一键与同一请求可重发 |
| GET | `?project_id=…&limit=20` | 按创建时间倒序查询当前项目的批次 |
| GET | `/{id}?after=0&limit=30` | 获取独立状态计数和逐项结果。用 `next_after` 向后翻页，或追加 `state=failed` |
| POST | `/{id}/pause`、`/{id}/resume`、`/{id}/cancel`、`/{id}/retry` | 暂停、恢复、取消、重新领取本批失败项 |

下面的请求使用示意 ID，需替换为项目内实际存在的记录和版本。两个素材槽各有两项备选，得到四份不同来源组合的草稿。

```json
{
  "project_id": "<project-id>",
  "name": "两种开头 × 两种证明镜头",
  "idempotency_key": "launch-summer-cut-01",
  "count": 4,
  "output": "timeline",
  "width": 720,
  "height": 1280,
  "fps": 25,
  "seed": 17,
  "slots": [
    {"choices": [
      {"asset_id": "<opening-a>", "version": 1, "source_in": 0, "source_out": 1},
      {"asset_id": "<opening-b>", "version": 2, "source_in": 1, "source_out": 2}
    ]},
    {"choices": [
      {"asset_id": "<proof-a>", "version": 1, "source_in": 0, "source_out": 2},
      {"asset_id": "<proof-b>", "version": 1, "source_in": 2, "source_out": 4}
    ]}
  ]
}
```

可把任意一个镜头换为 `{"generate":{"profile_id":"<video-profile>","prompt":"近景展示产品侧面的纹理","duration":2}}`。需要图片输入时，在 `generate` 对象同时提供 `reference_asset_id` 与 `reference_asset_version`。可在配方中提供 `"template":{"id":"<timeline-id>","version":3}` 以指定手剪样片。

接续已有工作流可提供 `"workflow_tail":{"id":"<workflow-id>","version":2,"node_id":"editor","input_path":"data"}`。选中端口的类型须接受本批输出，且该端口没有连接另一个上游节点。执行器保留原图，给每个序号绑定其实际产物版本。逐项响应中的 `workflow_run_id` 可用于读取检查点。`generation_jobs` 按镜头顺序记录配方中每个生成槽的任务、状态与已入库素材。工作流内部的生成任务在对应子运行的节点检查点中查询。

## 项目监测与两批对照

`GET /api/v1/production/batches/observability/health?project_id=…` 在同一个 SQLite 读取快照内统计正在排队、运行、等待、失败及成功的序号。队列年龄是仍在活动批次内的最老排队项从提交或重新入队到观测时刻的秒数。租约过期或缺失、当前失败按错误码分布，以及等待素材生成服务或子流程回执的项目数均可单独查看。暂停中的队列单列，已无正在排队的项目时年龄为空。读取接口不会触发重试或对外发送告警消息。

`GET /api/v1/production/batches/observability/compare?project_id=…&left=…&right=…&sample_size=8` 比较相同项目的两个批次。每小时吞吐量按成功序号数除以从提交到结束所经历的小时数计算，计入排队、暂停和回执等待。只有两个批次都已全部成功，且输出类别、画面尺寸、帧率与固定预期时长一致时，才返回右侧相对于左侧的吞吐比。样本规模、机器负载或执行路径可以不同，该比值只能用于描述这两次运行。GPU 时间及货币费用缺少单项实测值时为空。

固定抽样以双方共同拥有的序号范围为基准，等距选择最多 32 个位置；样本多于一个时包含首尾。每对样本读取已有时间线、实际源区间与顺序、成片字节数及摘要、完整解码结果和可核对的时长。这项对照不会创建新的模型请求或渲染任务。文件摘要、镜头序列的相同或差异只描述内容版本，不能推出哪条成片将有更好的投放效果。

## 版本化输出验收

可以从 `POST /api/v1/production/batches/contracts` 保存项目的输出要求。请求包含 `project_id`、`name`、`request_id` 和 `requirements`。更新时用 `previous: {id, version}` 声明正在修订的版本。批次通过可选的 `acceptance_contract: {id, version}` 固定所选契约，后续修订适用于显式选用新版本的批次。示例要求如下。

```json
{
  "width": 720,
  "height": 1280,
  "fps": 25,
  "duration_seconds": 15,
  "duration_tolerance_seconds": 0.08,
  "min_clip_seconds": 0.4,
  "max_clip_seconds": 3,
  "min_distinct_sources": 3,
  "min_editorial_roles": 2,
  "max_generation_calls": 100,
  "subtitle_language": "en-US",
  "require_full_decode": true
}
```

每个字段均可按实际目标取舍。系统先排除已知不可行的配方，然后逐项检查实际时间线；若选择输出成片，还会核对实际编码后可探测的宽高、帧率、时长和解码结果。镜头长度按实际入出点和播放速度计算。独立来源按源文件字节摘要去重。剪辑作用只使用人工锁定且证据覆盖所选完整区间的标签。字幕语种只核对含文本字幕的声明语种，不能证明翻译准确性。生成请求数检查使用冻结的整批调用上界。

单项中的 `acceptance` 列出时间线和编码阶段的 Audit 引用。每一项对照都保存期望、实际观测和结果。只能在编码后检查的项目在前置报告保留 `deferred`；硬门槛失败或未知会阻止该项计入成功。编码后的文件若未达业务契约，其文件与失败报告一并保留，便于复核。新补充的镜头证据可以在重试时形成新的报告；已完成的原报告保存在不可变事实账本中。接续工作流创建的其他产物由各自节点验收，上述契约针对本批次的主输出。

## 市场规则简报

P03-R2 可把同项目的原文 Script、本地化 Script、市场规则 Source、目标 Account 以及可选的 Product 绑定成 Brief。用 `POST /api/v1/production/batches/market-briefs` 提交项目、市场、目标语言、上述记录的精确版本、受众假设、禁止表达、有效期限和请求键。审阅身份签认精确简报版本后，配方可通过 `market_brief: {id, version}` 绑定。已有简报通过同路径的 GET 和 `project_id` 查询。

入队与执行前都会核对项目和账号市场、脚本文本与语种、商品和来源版本及有效期。若选择商品，原文和译文须保留完整 SKU 与相同的数字字面量；明确使用登记 ISO 币种的金额、可识别单位的件数须与商品凭据相符。人工样片在目标时段的字幕需声明相同语言，按时间排序后与核对脚本一致，且不得含简报明确禁止的表达。合格的时间线记录简报、审批、账号、脚本、来源、字幕摘要和适用期限。受众描述作为人工假设保存。这项检查以本地版本化事实、字幕元数据和明确的文本规则为据，翻译语义、文化适宜性以及平台账号真实发布能力须另行核实。
